# Spec Delta

## Purpose

该能力用于按北京时间生成可追溯的 GitHub 日榜前十摘要，让用户每天看到统一口径、明确榜期且适合移动端阅读的热门开源项目清单。

## ADDED Requirements

### Requirement: 每日生成前一日榜单
系统 SHALL 默认在 Asia/Shanghai 时区每天 08:00 触发一次日报，并将目标榜期标记为触发日期的前一自然日。榜单数据 SHALL 采用执行时获取的 GitHub `daily` Trending 快照，并明确展示抓取时间与该滚动日榜口径，不将其表述为精确的自然日 Star 增量统计。

#### Scenario: 正常定时生成
- **WHEN** 北京时间到达每日 08:00 且定时任务被触发
- **THEN** 系统生成目标榜期为前一自然日的日报，并记录实际抓取时间和数据口径

#### Scenario: 定时任务延迟执行
- **WHEN** 调度平台在 08:00 之后才启动当日任务
- **THEN** 系统仍使用计划触发日期计算目标榜期，并在执行记录中保存实际开始时间

### Requirement: 保留 GitHub Trending 排名
系统 MUST 按 GitHub `daily` Trending 返回的原始顺序选取前十个有效仓库，不得使用总 Star 数重新排序。少于十个有效仓库时，系统 SHALL 输出所有有效仓库并标明数量不足。

#### Scenario: 数据源返回至少十个有效仓库
- **WHEN** 抓取结果包含至少十个可识别的公开仓库
- **THEN** 日报包含原始榜单顺序的第 1 至第 10 名

#### Scenario: 有效仓库不足十个
- **WHEN** 抓取结果中可识别的公开仓库少于十个
- **THEN** 日报包含全部有效仓库，并明确提示本次榜单不足十项

### Requirement: 输出项目关键信息
系统 SHALL 为每个榜单项目输出排名、仓库全名、GitHub 链接、中文简介、主要语言、总 Star 数和日榜新增 Star 数。数据源未提供的非关键字段 SHALL 显示为“暂无数据”，不得伪造数值。

#### Scenario: 项目元数据完整
- **WHEN** 数据源和仓库元数据接口返回全部所需字段
- **THEN** 该项目的所有规定字段均出现在日报中

#### Scenario: 可选元数据缺失
- **WHEN** 主要语言或日榜新增 Star 数等非关键字段缺失
- **THEN** 系统保留该项目并将缺失字段标记为“暂无数据”

#### Scenario: 仓库身份不可解析
- **WHEN** 榜单条目无法解析出合法的仓库全名或 GitHub 链接
- **THEN** 系统排除该条目、记录原因，并继续处理后续排名

### Requirement: 生成可靠的中文简介
系统 SHALL 优先保留已有中文简介；对于英文简介，系统 SHALL 生成不改变项目用途的简洁中文摘要。摘要服务不可用时 MUST 回退到原始简介或明确的缺省文本，不得阻止整份日报生成。

#### Scenario: 原简介为中文
- **WHEN** 仓库简介已经包含可读中文
- **THEN** 系统直接使用原简介，不重复翻译

#### Scenario: 英文简介成功转换
- **WHEN** 仓库简介为英文且摘要服务可用
- **THEN** 日报展示忠于原意的简洁中文简介

#### Scenario: 摘要服务不可用
- **WHEN** 中文摘要生成失败或超过超时时间
- **THEN** 系统使用原始简介或缺省文本继续生成日报，并记录降级事件

### Requirement: 校验数据新鲜度
系统 MUST 在发送前确认榜单快照由本次运行获取且目标榜期正确。主数据源失败时，系统 MAY 使用兼容备用源；备用数据无法验证新鲜度时，系统 SHALL 终止正式发送并留下失败记录。

#### Scenario: 主数据源成功
- **WHEN** GitHub Trending 页面返回可解析的当前日榜
- **THEN** 系统使用该结果生成日报并记录来源

#### Scenario: 主数据源失败但备用源有效
- **WHEN** 主数据源不可用且备用源返回带有效生成时间的同口径日榜
- **THEN** 系统使用备用结果，并在执行记录中标记降级来源

#### Scenario: 所有来源均不可验证
- **WHEN** 没有数据源能提供可解析且新鲜的日榜
- **THEN** 系统不生成待正式推送的日报，并记录明确失败原因

### Requirement: 保存榜单快照和执行状态
系统 SHALL 按目标榜期保存规范化榜单快照、内容摘要值和执行状态，以便审计、幂等判断及手动补发。日志 MUST 对密钥和敏感参数进行脱敏。

#### Scenario: 首次生成榜单
- **WHEN** 某目标榜期尚无成功快照
- **THEN** 系统保存榜单内容、抓取时间、来源、内容摘要值和生成状态

#### Scenario: 相同榜期重复生成相同内容
- **WHEN** 相同目标榜期已存在相同内容摘要值的成功快照
- **THEN** 系统复用现有快照，并将本次执行标记为重复运行

### Requirement: 支持手动预览与指定榜期补发
系统 SHALL 提供手动执行入口，可生成预览但不发送，也可在明确指定目标榜期后请求补发。补发 SHALL 使用已保存快照；若不存在快照，系统必须先按正常校验规则重新获取数据。

#### Scenario: 手动预览
- **WHEN** 操作者以预览模式触发任务
- **THEN** 系统生成并展示消息内容，但不调用任何推送服务

#### Scenario: 指定榜期补发
- **WHEN** 操作者明确指定一个历史目标榜期并确认补发
- **THEN** 系统使用该榜期的有效快照创建一次带补发标记的发送请求
